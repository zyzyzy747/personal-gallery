# 写真图库 · 新界面视觉风格手册

> 一套面向「本地写真图库浏览」的完整视觉风格。素材取自 `E:\download\Telegram` 实测（5,292 套图 / 72,732 张 / 11.74 GB），所有色值、尺寸、比例均有实测依据，无「适度圆角」类模糊表述。

---

## 一、美学主张

> **这是一个「暗房里的档案柜」——照片是藏品本身，界面是贴在照片旁边的索引卡，而不是一个装照片的网页。**

三条可执行原则：

1. **照片是唯一发光体。** 界面中性色全部压在暗部区间，UI 元素明度不得高于图片中位亮度的四分之一。界面负责「不打扰」，不负责「好看」。
2. **信息是档案，不是装饰。** 目录名里的真实语法（coser / 主题 / 数量 / 体积 / 标签）必须被拆解并重新赋予层级，而不是原样打印成一坨字符串。索引卡的排版精度是本产品全部的视觉价值。
3. **冷色工具，暖色内容。** 工具部分（导航、筛选、控件）一律冷调去饱和，把全部色彩预算留给照片。

**审美坐标**：不用 Netflix 的「海报墙」（影视流媒体语法），也不用 Pinterest 的「瀑布流」（灵感聚合语法）。本项目是**本地归档与检索工具**，参照物是摄影暗房的接触印样（contact sheet）与图书馆卡片目录：安静、致密、信息优先、无推荐流。

## 二、这套风格的决策依据（实测数据）

配色不是审美偏好推导出来的，是被素材逼出来的。

| 素材事实 | 实测值 | 对设计的强制约束 |
|---|---|---|
| 像素色相气候 | 暖色（0–50°）**51%**、冷色（240–280°）13.5% | UI 底色必须冷中性。暖底 + 暖图 = 边界糊掉，主体陷进背景 |
| 每图主色聚类 | 暖色主导 66.2% / 冷色 3.1% / 中性 30.6%，平均主色 `#9B7173` | 冷暖对立是唯一稳定的主次分离手段 |
| 素材饱和度 | 中位 **0.247**，63% 的图平均饱和度 < 0.15 | UI 饱和度必须 ≤ 0.12，否则界面比照片抢眼 |
| 素材对比度 | 中位 **0.215** | UI 边框对比度 ≤ 图片中位对比度的一半 |
| 单图亮度 | p05 0.217 / p50 0.527 / p95 0.763 | 最亮 UI 表面（Y=0.0208）比最暗 5% 图片暗 **10.4 倍** → 图片必然「发光」 |
| 图片边缘亮度 | 6px 边框 p05 0.139，5.0% 的图边框近黑 | **禁止纯黑背景**；每张图必须带 1px 内描边 |
| 构图比例 | 竖 77.3% / 横 21.8% / 方 0.8%（n=600，独立抽样复核视觉方 77.9/21.3/0.8） | 封面裁 3:4；详情页瀑布流**按原生比例不裁切** |
| 主力尺寸 | 853×1280、960×1280、1280×853 | 缩略图基准宽 240px；原图可直接本地解码 |
| 套图规模 | p10 5 / p50 10 / p90 20 / max 877 张 | 详情页需支持快速横滑；列表页只出封面 |
| 标签体系 | 约 3,700 个归一化标签（随图库增长），但 works 仅 54 个、roles 234 个、themes 256 个，others **2,858** 个长尾 | 分面要分维度，「未分类」默认折叠 |
| 元数据完整度 | **26.3% 套图零标签**，41.9% 仅未分类 | 卡片必须有降级呈现，不能假设有标签可显示 |
| 运营目录 | 9 个 `📌 近期精选（点击预览 👀）` 类 | 默认隐藏，否则污染搜索结果 |

> 两套独立方法交叉验证：你自己的像素级采样（按色相家族）与主理人的按图主色聚类，得出同一个结论（暖色主导 51% vs 53.2%）。这条链路可信。

**为什么强调色选 H189 青蓝**：素材里 H185–195 青蓝区只占 3.3%，是**最稀缺的色相**——它永远不会与照片内容混淆，用户永远不会把一个 UI 按钮误认成照片里的东西。同时它与素材 51% 的暖色构成稳定的温度对立。

| `--lt-accent` | `#1F7A8A` | 4.49 |

**换色规则**：暗色的 `#4FB3C4` 在白底上对比度只有 2.21，不可用。浅色必须换成同色相压暗的 `#1F7A8A`。深浅主题共用同一套语义 token 名，只换值。

### 3.3 硬约束

1. 界面里**不允许出现纯黑 `#000`**，也不允许纯白作大面积背景。照片才是画面里最亮和最暗的东西。
2. **强调色只有一个**（冷青蓝）。琥珀色是档案章，只在物理属性上出现，**绝不作按钮底色**。
3. 中性色相锚定 **H218–231**（冷灰蓝）。
4. 任何 UI 填充色 **HSL S ≤ 50%、L ≤ 64%**。
5. 深浅主题共用语义 token，**组件里禁止写死 hex**。

**核心排印逻辑 —— 目录名的拆解与重排**：

原始目录名如 `#纸悦Etsu_ko - #鸣潮 #爱弥斯 [25P-134MB]` **绝不能原样显示**。必须拆成三个层级：

```
[纸悦Etsu_ko]              ← coser 胶囊（accent-wash 底，青蓝）
鸣潮 · 爱弥斯                ← 标题行（works 优先，其后 roles，· 分隔）
25P · 134MB                 ← 档案章行（amber-wash 底，mono）
```

中英日混排规则：中文与拉丁字母之间不加空格；日文标签（`生誕写真集`）按中文处理；emoji 标签按 §7.8 三档处理。

## 五、图片呈现规范

### 5.1 目录墙（主界面）

| 参数 | 值 |
|---|---|
| 容器最大宽 | 1680px 居中 |
| 内边距 | 32px（≥1024）/ 20px（768–1023）/ 14px（<768） |
| 列数 | ≥1440: 6 · 1100–1439: 5 · 860–1099: 4 · 620–859: 3 · 400–619: 2 · <400: 1 |
| 横向间距 | 24px |
| **纵向间距** | **32px**（大于横向 —— 把卡片与其下方的索引卡文字区绑成一组，这是「档案柜」隐喻的关键） |
| 封面比例 | `aspect-ratio: 3 / 4` |

### 5.2 封面选取与裁切

1. 套图内按文件名日期升序取前 ≤6 张
2. 优先选**比例 ≤ 0.80** 的（77.3% 的素材满足）
3. 全为横构图时取第一张，`object-position: 50% 35%`
4. 一般情况 `object-fit: cover` + `object-position: 50% 28%`（人物头部保留优先）

### 5.3 圆角一致性（易错点）

| 层级 | 圆角 |
|---|---|
| 图片本体 / 缩略图 | **8px**（唯一的媒体圆角） |
| **裁切图片的父容器** | **8px**（父容器圆角必须 = 被裁切图片圆角，否则四角出现 4px「月牙」错位） |
| 按钮 / 输入框 / 分面行 | 6px |
| 可点筛选胶囊 | 999px |
| 静态标签片 | 4px（矩形片，读作「数据」而非「按钮」） |
| 档案章 | 3px |
| 头像 | 50% |
| 灯箱内的图 | **0px**（全屏看图不该有圆角） |

### 5.4 加载态（三级瀑布，禁用灰色骨架屏）

`模糊占位 (LQIP, blur 14px)` → `淡入 (160ms)` → `完整`。每张图带 1px `rgba(255,255,255,.08)` 内描边，形成「相纸边缘」——这是照片墙不发糊的关键。

规则：胶囊内**不加 `#`**（前缀语义由样式承担）；标签片**最多 3 个**，其余折 `+N`；标签**不换行**，超长省略；同屏内强调色胶囊数量应远少于中性标签片，保持「少数派是重点」。

### 6.2 卡片结构

```
┌─────────────────┐
│                 │  封面 3:4，圆角 8px，内描边 1px
│      封面        │  ← 索引卡区上边缘 32px
│                 │
├─────────────────┤
│ [coser]         │  胶囊 20px 圆角 4px，accent-wash
│ 鸣潮 · 爱弥斯    │  标题 14px/600
│ [泳装][JK][+2]  │  标签片行，最多 3 个
│ 25P · 134MB     │  档案章行，amber-wash mono
└─────────────────┘
```

**降级方案（26.3% 套图零标签）**：无标签时省略标签片行，索引卡区高度**保持恒定**（用 min-height 锁定），避免网格参差。

按钮（主 / 次 / 幽灵 / 图标）、搜索框、筛选侧栏、顶部导航、详情抽屉、灯箱、空状态、骨架屏的完整参数见 `docs/01-visual-direction.md` §6。

## 七、细节质感

- **阴影层级**：4 档，全部为中性黑低透明，禁止彩色阴影（会与照片争色温）
- **1px 边框**：唯一允许的第四种「视觉噪声」来源，用于分隔而非装饰
- **玻璃拟态**：**不用** `backdrop-filter`。实测顶栏与灯箱顶栏均用实色背景 + `rgba(8,9,11,.86)`
- **渐变**：仅两处 —— 图片上的文字遮罩（`--scrim`，自下而上 0.88→0）、灯箱渐晕（`--lb-vignette`）
- **图片圆角与卡片圆角一致**：父容器 = 图片 = 8px
- **动效**：入场 160ms / 悬停 120ms / 面板 180ms，统一 `--ease-out`；`prefers-reduced-motion` 下全部降为 0ms
- **焦点态**：双层环 `0 0 0 2px bg-base, 0 0 0 4px accent`，2px offset，键盘可达

### 敏感内容处理（NSFW）

素材库含 `cosplay 写真[NSFW]` 分组。设**全局开关**（默认开启）：

| 档位 | 封面 | 灯箱 |
|---|---|---|
| 模糊（默认） | `filter: blur(18px) saturate(.85)` | 不加载原图，显示占位 |
| 悬停/聚焦 | 临时解除模糊 | — |
| 关闭开关 | 原样显示 | 原图直出 |

开关状态持久化到 localStorage，位置在侧栏顶部，显著但不抢戏。

## 八、禁用清单（三条）

1. **禁止纯黑背景 `#000000`** —— 实测 5.0% 的图片边缘本身接近纯黑，纯黑底会让这些图的边界彻底消失，变成"浮空的一块黑"。改用 `#0E0F12`（H225 S12.5% L6.3%）—— 带一点冷色，和暖调照片拉开色温。
2. **禁止霓虹紫 / 赛博粉紫渐变（及任何 UI 强调色 S > 60%）** —— 素材里 63% 的图平均饱和度已低于 0.15，界面再用高饱和色就是喧宾夺主；且素材里确有紫色内容（4.4% 像素），紫色强调色会被误认成照片内容。
3. **禁止在图片上直接叠加标题文字 / 禁止"大圆角卡片 + 阴影"的作品集模板** —— 素材图本身色彩复杂，叠字必然牺牲可读性（WCAG 4.5:1 无法保证）；且 21.8% 的横构图会被大圆角切掉人物。信息应放在图**下方**的索引卡区，而不是压在图上。

### 日常维护：新增图片

后续往 `E:\download\Telegram` 继续下载，**双击 `启动图库.bat` 即可**——它会先做增量更新再起服务。

增量之所以快，是因为 `build.py` 幂等：已存在的封面/分片直接跳过。实测新增 60 套 **6.3 秒**、
新增 396 套 **13.4 秒**，而首次全量 5292 套需 3 分 32 秒。

代价是 `id` 必须是**稳定标识**而非排序序号——否则新增一个张数更大的套图会让所有 id 平移，
5292 张缩略图整体错位成别人的图。现在 id 从旧索引沿用、新套图追加，实测老缩略图零重写。

目录名推荐 `#coser - #作品 #角色 #主题`；`#coser 作品 角色`（空格分隔）也能识别，
靠「内联标签救援」规则用已知 coser 词表做最长前缀匹配，实测救回 1589 套。
